# ADR-0008: Single-source grammar — the JSON Schema is a generated projection

**Status:** Accepted

**Context** — The PDL grammar was declared in two places that had to agree by hand: the parser's key sets and the published `titan-pipeline.schema.json` (editor/tooling contract). Adding a key meant editing both, and nothing failed if you forgot the schema — the parser still accepted the YAML while the editor lied about it. That is a silent drift surface that grows with every grammar change. Generating the schema solves the drift, but only if generation is driven by explicit typed declarations — generating via classpath reflection trades the drift for implicit, unstable output.

**Decision** — The grammar is declared once, as explicit typed data in `TitanGrammar`, and each `StepScope` owns its own `GrammarKey` schema next to its parse code. The parser's key validation and the published JSON Schema are both projections of that single declaration; the schema is generated by `TitanSchemaGenerator`, never hand-authored.

**Consequences**
- One scope class is one PR that moves parser and schema together by construction; they cannot drift.
- A drift-guard unit test (`TitanSchemaGenerationTest`) regenerates the schema in memory and fails the build if the committed file differs, with a one-line fix.
- The committed schema file stays reviewable in diffs and greppable — generation is enforced by the test, not wired into the build's resource phase.
- The per-step descriptor argument catalog stays open (`additionalProperties`), because step handlers are an extensible SPI not visible to the controller schema (see ADR-0012).
